## Hygiene rules

For each featured repository:

- Keep the first screen evidence-heavy: purpose, status, architecture, demo.
- Keep claims matched to actual implementation status.
- Keep CI failures or blockers visible rather than implying production readiness.
- Add release tags when the repository is genuinely releasable.
- Prefer screenshots, benchmarks, tests, demos, PRs, and commits over decorative claims.

### Profile / repository presentation

- Feature the current civic integration work before historical CIVWATCH material.
- Keep Nine Realities visible as the deepest systems / distributed-engineering proof.
- Use badges and trophies as an achievement layer, not as a substitute for evidence.
- Maintain dynamic activity widgets through GitHub Actions where possible.
